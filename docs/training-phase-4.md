# 算法训练升级：阶段 4 验收

阶段 4 在阶段 3 的实时监控基础上，补齐训练制品登记、安全下载、失败分类、超时与执行器失联处理、任务审计、并发限制和受控磁盘清理。阶段 4 只处理可靠性与制品管理，不进入后续模型发布或推理功能。

## 数据模型与迁移

迁移文件：`fastapi-app/migrations/006_training_reliability.sql`

`training_jobs` 新增：

- `failure_code`：机器可读的失败分类
- `timeout_seconds`：任务最长运行时间快照
- `cleanup_status` / `cleaned_at`：远程制品保留或清理状态
- `reconcile_failures`：连续执行器通信失败次数

`training_artifacts` 新增：

- `artifact_role`：制品语义角色
- `downloadable`：是否允许通过受控接口下载

新表 `training_audits` 记录任务创建、启动、完成、停止、重试、下载、清理等操作，包含操作者、角色、结果、消息、结构化载荷和时间。

## 制品登记

训练终态会登记：

- `TRAIN_LOG`：`raw.log`
- `TRAIN_CONFIG`：`config.json`
- `EXECUTION_COMMAND`：`command.json`
- `RUN_MANIFEST`：`manifest.json`
- `EVALUATION_RESULT`：`results.csv`
- `BEST_CHECKPOINT` / `LAST_CHECKPOINT` / `AUXILIARY_CHECKPOINT`
- `EVALUATION_VISUALIZATION`

旧任务首次打开详情时会按远程清单补录阶段 4 角色。无法识别或不适合直接下载的文件保留为 `OTHER`，默认禁止下载。

下载接口：

```text
GET /training/jobs/{job_id}/artifacts/{artifact_id}/download
```

下载前会同时校验：

- 当前用户拥有任务，或当前用户是管理员
- 制品属于该任务
- 任务尚未清理，制品标记为可下载
- 远程路径是任务运行目录内的普通文件

响应使用附件下载、准确的 `Content-Length`、`Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`。下载行为写入审计表。

## 失败分类与资源回收

失败码：

- `CUDA_OOM`：CUDA 显存不足
- `DISK_FULL`：磁盘空间或配额不足
- `TIMEOUT`：超过任务最长运行时间
- `ABNORMAL_EXIT`：非零退出码
- `EXECUTOR_LOST`：远程启动失败或连续三次无法对账
- `USER_STOPPED` / `CANCELED`：人工停止或排队取消
- `LAUNCH_FAILED` / `UNKNOWN_FAILURE`：启动失败或未命中已知分类

CUDA/OSError/RuntimeError 等关键错误行会持久化，终态分类会结合退出码、已有停止原因和最近日志。超时后复用受控进程组停止流程；正常结束、失败、停止或失联后都释放数据库 GPU 租约。连续一两次 SSH 对账失败不会立即误判，第三次才进入 `LOST`。

本阶段真实训练发现，Tortoise 在 `use_tz=True` 时将 MySQL `DATETIME` 写为 UTC，若与服务器本地 `NOW()` 比较会产生 8 小时偏差。启动宽限和运行超时现统一使用 `UTC_TIMESTAMP(6)`，避免刚启动任务被误判超时。

## 并发、GPU 与清理边界

配置项：

- `TRAINING_MAX_CONCURRENT_JOBS=4`
- `TRAINING_MAX_RUNTIME_SECONDS=21600`
- `TRAINING_ARTIFACT_RETENTION_DAYS=30`
- 原有每用户排队上限与 GPU 白名单继续生效

全局运行任务达到并发上限时，新任务保留在 `QUEUED`。GPU 仍只能从管理员白名单选择。

清理接口只允许管理员使用：

```text
GET  /training/jobs/{job_id}/cleanup-preview
POST /training/jobs/{job_id}/cleanup
```

清理仅接受终态任务，并要求数据库中的运行目录和控制目录与配置根目录及任务 UUID 精确一致。删除命令使用经过验证的两个绝对路径，不接受用户传入路径。清理成功后制品统一标记为不可下载，任务显示 `CLEANED`，操作写入事件和审计记录。

## 管理员任务管理补充

迁移文件：`fastapi-app/migrations/007_training_admin_management.sql`

管理员任务列表默认只展示未归档任务，并可切换“未归档 / 已归档 / 全部任务”。已结束任务的管理员操作集中在“更多”菜单：

- `归档任务`：从默认列表隐藏，保留任务详情、日志、指标、产物和审计
- `恢复归档`：将任务恢复到默认列表
- `清理远程产物`：沿用阶段 4 的受控清理
- `彻底删除`：仅在任务已归档且产物已清理时显示为可操作

彻底删除还会在后端再次确认：

- 任务处于终态
- 不存在引用当前任务的重试任务
- 远程运行目录和控制目录均不存在
- 远程进程列表不存在包含任务 UUID 的进程
- 管理员输入的完整任务编号与数据库一致
- 删除原因不少于 3 个字符

通过校验后，任务及其明细记录在同一数据库事务中物理删除。删除前会把任务关键信息和完整审计链写入无外键的 `training_job_deletions` 存根表，因此任务从业务列表消失后仍能追溯删除人、删除原因和历史操作。事务失败时，删除审计和存根均不会产生半完成状态。

普通用户始终只能看到自己的未归档任务，即使手工传入“全部任务”筛选也不能读取归档任务；归档、恢复和彻底删除接口均只允许管理员。
